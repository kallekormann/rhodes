## TD-001 — Multi-conflict misclassification

### Repro (from 09.1 UAT, July 27, 2026)

| Block | Offline (User A) | Online | UI result |
|-------|------------------|--------|-----------|
| Block 1 | Edited | User B removed block | ✅ Correct conflict |
| Block 2 | Edited one word | User C edited same word | ❌ UI says User C **removed Block 2** |

### Hypothesis

When multiple conflict clusters are queued in one offline return session, classification for cluster 2+ may inherit block-level delete semantics from cluster 1, or span/cluster coalescing treats the second block as structurally removed when only inline text diverged.

### Suggested slices

1. **Regression test** — extend offline test suite with a two-cluster fixture (block delete + inline word overlap). Commit: `test(offline): multi-conflict block delete + inline word overlap fixture`
2. **Fix cluster boundary / attribution** — smallest change in span/cluster or `peer-edit-contributions` so Block 2 surfaces as span conflict. Commit: `fix(offline): classify inline conflicts correctly in multi-cluster review`
3. **UAT** — re-run [09-m1-exit-collab-offline.md](09-m1-exit-collab-offline.md) steps 3–4 **plus** the TD-001 repro above with 3 users.
